# 실행·협업·복구 운영 가이드

제출자: 강준권 · 정리일: 2026-11-14

미션02는 Python 표준 라이브러리를 사용하는 **개인용·단일 프로세스 CLI 학습 프로그램**입니다.
아래는 현재 동작과 운영 권고를 구분한 설명입니다. 새 언어팩, 입력 제한, 잠금, DB 전환, 백업 정리 같은 기능을 구현했다고 주장하지 않습니다.

## 1. Windows와 Ubuntu 실행 차이 — 평가 1번

프로젝트 폴더에서 다음 중 현재 환경에 맞는 한 행을 사용합니다.

| 환경 | 버전 확인 | 게임 실행 | 검증 실행 | 출력·주의사항 |
|---|---|---|---|---|
| Ubuntu / WSL Ubuntu | `python3 --version` | `python3 main.py` | `python3 scripts/verify_submission.py --output evidence/precheck_local` | Linux 경로와 `$` 프롬프트 사용 |
| Windows PowerShell | `python --version` | `python main.py` | `python scripts/verify_submission.py --output evidence/precheck_local` | Windows 경로와 `PS ...>` 프롬프트 사용. Python 명령이 설치·등록돼 있어야 함 |

`--version`은 Python 버전 확인, `main.py`는 시작 파일, 검증 명령의 `--output`은 결과 폴더 지정입니다.
출력의 메뉴·한국어 정답 안내는 두 환경에서 같고, Python 버전·경로·운영체제·측정 시간은 달라집니다.
Windows에서 `python`이 없으면 설치된 런처의 `py -3` 사용 가능 여부를 확인합니다. 이 런처는 이번 검증에서 사용하지 않았습니다.
PowerShell에 Ubuntu용 `sudo`, `chmod`를 그대로 입력하지 않습니다. `$`와 `PS ...>`는 입력할 명령 자체가 아닙니다.
별도 폴더에서 시작하려면 먼저 실제 프로젝트 폴더로 이동합니다. `state.json`은 현재 작업 디렉터리가 아니라 `main.py` 옆에 저장됩니다.

실제 검증 환경은 기존 Ubuntu/Python 3.14.4와 추가 Windows/Python 3.12.14이며 버전·OS·명령·종료 코드는 evidence에 있습니다.
설치 경로가 다른 PC에서 위 명령이 자동으로 설정되는 것은 아닙니다. `ModuleNotFoundError` 등 오류면 파일 전체가 같은 폴더에 있는지 확인합니다.

## 2. 입력 실패·동시 실행·기본 문제 호환 — 평가 2~4번

**입력 운영 정책:** 잘못 입력하면 횟수 제한 없이 같은 질문을 반복합니다. 화면 안내만 출력하고 별도 입력 오류 파일 로그나 국제화(i18n)는 구현하지 않았습니다.
교육 중 실수로 프로그램이 종료되지 않게 하려는 선택입니다. 취소는 Ctrl+C 또는 EOF, 정상 종료는 메뉴 5번입니다.
오류 입력 원문을 파일에 저장하지 않으므로 입력할 수 있는 개인정보도 별도 오류 로그에 수집하지 않습니다.
향후 무인·외부 서비스로 전환할 때에는 취소 버튼/명령, 재시도 제한, 개인정보 없는 오류 분류·횟수 집계를 별도로 설계합니다.

**동시 실행 정책:** 같은 `state.json`은 반드시 한 창·한 프로세스만 사용합니다. 다른 터미널을 열어도 먼저 게임을 종료한 뒤 실행합니다.
두 프로세스가 옛 상태를 각각 저장하면 앞선 변경이 사라질 수 있으며, `os.replace`만으로 이 충돌을 막지 못합니다.
여러 사람이 쓰려면 각각 다른 폴더/저장 경로를 사용하고, 공용 기록이 필요하면 잠금·트랜잭션 설계를 먼저 검증합니다.

**기본 문제 호환 정책:** `defaults.py`를 수정해도 유효한 기존 `state.json`의 퀴즈와 점수는 유지하며 자동 병합·교체하지 않습니다.
새 기본값 확인은 별도 임시 복사본의 첫 실행으로 합니다. 기존 기록에 새 문제를 넣을 때는 메뉴 2번으로 등록합니다.
기존 문제의 일괄 교체는 자동 지원하지 않습니다. 새 기본 문제 구성으로 완전히 시작해야 한다면 먼저 옛 코드와 state.json을 보관하고,
별도의 새 작업 복사본에서 새 기본값으로 시작합니다. 그 복사본에는 예전 추가 문제·점수가 자동 이전되지 않으며 원래 작업 폴더는 유지합니다.

## 3. 원격 접근·태그·병합·인증 — 평가 5~7번

2026-11-14 GitHub 저장소 메타데이터로 확인한 주소는 `https://github.com/damagez7788-cyber/codyssey-mission02`,
접근 상태는 **public(공개)**, 기본·제출 브랜치는 **main**입니다. `codex/quiz-play`는 퀴즈 풀기 개발 브랜치이며 `7047523`으로 병합했습니다.
공개는 누구나 내용을 읽을 수 있다는 뜻이며, 쓰기는 소유자 또는 쓰기 권한을 가진 인증 사용자만 할 수 있습니다.
이번 보완에서 공개 범위·계정 권한은 바꾸지 않습니다. 개인정보·비밀번호·토큰·개인 `state.json`은 커밋하지 않습니다.

**태그/릴리스 정책:** 현재 제출 기준은 `main`의 커밋 ID입니다. 이 보완에서 태그나 GitHub Release를 새로 만들지 않습니다.
나중에 정식 버전을 배포한다면 검증된 커밋에 `v1.0.0` 같은 태그를 붙이고 변경·호환성을 릴리스 설명에 남깁니다.
이는 향후 규칙이며 해당 이름의 태그가 지금 존재한다는 뜻이 아닙니다.

**병합 전략:** 기능 브랜치를 `main`에 merge해 기능 이력과 병합 관계를 남깁니다. 이미 공유한 이력은 rebase나 force push로 다시 쓰지 않습니다.
이번 실제 병합에 충돌이 있었다고 주장하지 않습니다. 충돌이 생기면 양쪽 변경을 읽고 의도를 확인 → 파일 수정 → 관련 검사 → 변경 선택·커밋 순서로 처리합니다.
해결할 수 없으면 병합을 취소하고 논의합니다. 혼자 아직 공유하지 않은 작업을 정리할 때의 rebase와 공유 브랜치 병합은 구분합니다.

다음은 **조회용 명령**이며 GitHub 인증정보를 출력하지 않습니다.

```bash
git remote -v
git branch -vv
git status
```

`remote -v`는 fetch/push 대상, `branch -vv`는 브랜치·추적 관계, `status`는 변경 상태입니다.
다른 저장소를 가리키면 push를 멈추고 올바른 주소를 확인합니다. URL에 토큰·비밀번호를 끼워 넣지 않습니다.
`clone`(새 복제)이나 `pull`(가져오기) 전에 원격 주소를 확인하고, 비공개 저장소는 읽기 권한도 확인합니다.
접근 거부·401/403이면 GitHub 로그인 계정과 저장소 권한을 확인합니다. Git 사용자 이름·이메일 설정은 로그인 인증과 다릅니다.
인증 갱신은 기존 인증 도구의 브라우저 로그인을 사용하고 비밀번호·토큰을 코드·README·터미널 로그에 적지 않습니다.
`pull --ff-only`가 이력 분기로 실패하면 강제로 덮어쓰지 말고 양쪽 커밋을 비교한 뒤 병합 방법을 정합니다.

## 4. 예외 처리 경계와 인터페이스 변경 — 평가 8~9번

예외의 호출 경로는 `main.main → QuizGame.run → 메뉴 메서드 → 입력 함수 / Quiz / StateStore`입니다.

| 발생 위치 | 예외·처리 주체 | 호출자에게 전달되는 결과 |
|---|---|---|
| `input_utils.read_number` | 정수 변환 ValueError를 함수 안에서 처리 | 안내 후 재입력. 성공하면 int |
| `input_utils.read_text` | 공백은 예외 대신 함수 안에서 재입력 | 성공하면 비어 있지 않은 str |
| `Quiz.__init__`, `Quiz.from_dict` | 잘못된 데이터는 ValueError, 누락 키는 KeyError 가능 | 직접 재사용하는 호출자가 처리. 파일 로드 중이면 StateStore가 처리 |
| `StateStore.load` | 파일 없음은 기본값. 데이터 형식 오류는 손상 원본 보관. 읽기/보관 OSError는 저장 제한 | 퀴즈·점수·풀이 여부·최고 기록의 4개 값 반환 |
| `StateStore.save` | 쓰기·교체 OSError를 내부 처리 | False와 오류 안내. 성공이면 True |
| 입력 도중 Ctrl+C / EOF | 입력 함수는 전파, `main.main`이 KeyboardInterrupt/EOFError 처리 | `finish()`로 저장 시도 후 종료 |

예상하지 않은 프로그래밍 오류까지 `except Exception`으로 숨기지 않습니다.
예를 들어 직접 Quiz를 만드는 외부 코드는 ValueError를 처리해야 하며, StateStore.save에 허용되지 않은 객체를 넘기는 오류까지 저장 성공으로 바꾸지 않습니다.

핵심 함수의 인자·반환값을 바꿀 때에는 다음 표를 확인합니다.

| 변경 인터페이스 | 직접 영향받는 호출 위치 | 함께 갱신할 곳 |
|---|---|---|
| `read_number(prompt, minimum, maximum) → int` | `game.py`의 run/add_quiz/play | tests의 입력 오류·메뉴·정답 범위, 입력 안내 문서 |
| `Quiz(question, choices, answer)` / `from_dict(item)` | defaults.py, game.add_quiz, storage.load, 재사용 코드 | 선택지·정답 검증, JSON 예시, 왕복 검사 |
| `StateStore.load() → 4개 값` | `QuizGame.__init__`의 언패킹 | scripts/verify_submission.py, 저장·복구 tests, JSON 문서 |
| `StateStore.save(quizzes, best_score, played, best_result) → bool` | QuizGame.save 및 직접 저장 호출 | 저장 실패 분기, benchmark, tests, API 표 |

인터페이스 변경 체크리스트: 정의 → 모든 호출처 → 반환값/예외 → 저장 스키마 → 기존 파일 호환 → 자동 검사/실제 CLI → README 순서로 대조합니다.

## 5. 중요한 기록의 백업·종료 — 평가 10~11번

현재 임시 쓰기·닫기·교체는 부분 쓰기 위험을 줄이지만 `fsync`, 프로세스 간 잠금, SIGTERM 처리기를 추가한 것은 아닙니다.
중요한 데이터라면 **작업 시작 전과 종료 후, 장시간 작업은 하루 1회 이상** 정상 기록을 날짜별 외부 폴더에도 복사하는 수동 백업을 권합니다.
게임을 한 창에서 메뉴 5번으로 정상 종료하고, 저장 실패 안내가 없고 재실행 때 기록이 맞는지 확인한 뒤 백업합니다.
저장 실패 상태의 파일만 복사해 현재 메모리의 미저장 변경까지 보존됐다고 생각하지 않습니다.
백업 파일은 별도의 검증용 프로그램 복사본의 state.json으로 복사한 뒤 실행해 퀴즈 수·최고 기록을 비교합니다. 원본 작업 폴더에서 복원 시험하지 않습니다.
같은 디스크의 백업만으로 디스크 고장에 대비할 수 없으므로 중요한 정상본은 사용자가 승인한 별도 저장 장치에도 보관합니다.
파일이 남아 있어도 SIGTERM·강제 종료 직전의 미완성 입력이나 아직 저장하지 않은 변경은 사라질 수 있습니다.

종료 요청은 먼저 사용자가 메뉴 5번 또는 Ctrl+C로 마칠 수 있게 합니다. **자동화 환경은 SIGTERM을 보내기 전에 수동 종료를 요청하고 완료를 기다립니다.**
바로 강제 종료하면 진행 중 입력은 잃을 수 있습니다. 운영체제 강제 종료를 안전 종료로 취급하지 않습니다.

아래는 프로젝트 폴더에서 게임이 종료된 뒤 실행하는 **수동 백업 예시**입니다. 실제 자동 예약 기능은 없습니다.

```bash
mkdir -p "$HOME/mission02-backups"
cp -p -- state.json "$HOME/mission02-backups/state-$(date +%Y%m%d-%H%M%S).json"
```

첫 줄은 백업 폴더 준비, 둘째는 기존 state.json을 날짜·시각을 붙인 새 파일로 복사합니다.
`cp -p`는 가능한 파일 속성 보존, `--`는 뒤의 값을 파일 이름으로 해석하도록 하는 구분, `$(date ...)`는 현재 시각으로 이름을 만드는 부분입니다.
없는 state.json은 복사할 수 없으므로 첫 저장이 성공했는지 먼저 확인합니다. 위 명령은 Ubuntu용이며 Windows에서는 탐색기의 복사/붙여넣기로 별도 날짜 폴더에 보관할 수 있습니다.

## 6. 커밋 예시와 API 호환 정책 — 평가 12~13번

실제 커밋 단위는 한 목적의 코드·검사·설명 묶음입니다. 개수를 늘리기 위한 빈 커밋, 같은 변경의 불필요한 쪼개기, 날짜 위조,
검사하지 않은 결과를 통과라고 쓰는 행위는 금지합니다. 아래 두 건은 **형식을 설명하는 예시이며 실제 커밋 기록이 아닙니다.**

```text
제목: Feat: 퀴즈 등록 후 즉시 저장하고 저장 실패를 안내
본문:
변경 이유: 재실행해도 등록한 문제를 유지해야 합니다.
주요 변경: 완성된 문제만 추가하고 저장 성공/실패를 나눕니다.
검증: 등록·재실행·저장 실패 검사를 실제 실행한 결과로 작성합니다.
한계: 여러 프로세스의 동시 저장은 지원하지 않습니다.
```

```text
제목: Docs: 플랫폼별 실행 명령과 복구 정책 정리
본문:
변경 이유: Windows와 Ubuntu의 실행 방법을 구별하기 위함입니다.
주요 변경: 명령·예상 출력 차이·수동 복구 절차를 추가합니다.
검증: 문서의 호출 경로·명령과 실제 코드/로그를 대조한 결과를 적습니다.
한계: 구현하지 않은 운영 기능은 권고로 구분합니다.
```

실제 제목 사례는 `8c52a2d Feat: 별도 브랜치에서 출제와 정답 판정 및 최고 점수 갱신 구현`과
`79cd633 Docs: 사전평가 보완 설명과 실제 검증 근거 추가`입니다.
두 번째 커밋의 실제 본문·변경 파일은 [GitHub의 79cd633 기록](https://github.com/damagez7788-cyber/codyssey-mission02/commit/79cd633fe0fe20a585bfe26d8ba64f38b1e0e285)에서 확인할 수 있습니다.

**재사용 API 호환 정책:** 공개 메서드의 인자·반환값·예외 의미를 바꾸면 호환성 변경으로 기록하고 호출자·저장 파일 영향을 함께 설명합니다.
향후 버전은 문서에 표기하고, 호환성 유지가 필요하면 기존 호출을 보존하는 어댑터/단계적 폐기를 먼저 검토합니다.
현재 배포 태그·API 버전 필드를 새로 만들었다는 뜻은 아니며, 기존 클래스 호출 계약을 유지하는 것이 이번 보완의 기준입니다.
향후 버전 부여·어댑터·이관 실행은 아직 적용·검증하지 않은 계획이며 구현 상태와 구분합니다.

## 7. 대체 저장소 전환 판단 — 평가 14·16번

JSON은 이 개인용 학습 프로그램의 기본 저장소로 유지하며 **자동 DB 전환은 하지 않습니다**.
우선순위는 **① 단일/동시 작성자 여부 ② 데이터 크기·문제 길이 ③ 실제 저장/로드 지연·메모리 ④ 검색 빈도·부분 수정 빈도 ⑤ 이관·복구 가능성**입니다.
공유 작성자가 2개 이상 필요하면 문제 수와 관계없이 현재 JSON의 무잠금 방식부터 재설계합니다.
**5,000문제 이상부터 DB 전환 검토를 시작**하는 운영 기준을 제안합니다. 이는 이번 프로젝트의 보수적인 검토 시점이며 성능 한계나 보편 기준이 아닙니다.
이번 10,000문제 저장 중앙값은 약 0.613초, 읽기는 약 0.209초였지만 한 PC의 합성 데이터 결과입니다.
실제 사용에서 저장·읽기 대기가 반복적으로 1초를 넘거나 전체 재쓰기/메모리가 불편해지면 더 적은 문제에서도 전환을 검토합니다. 이 1초도 사용성 목표 예시입니다.

SQLite 도입 시 자동 전환보다는 명시적인 오프라인 이관을 우선하고, 문항 ID·테이블·검색 인덱스·트랜잭션·잠금 대기·검사를 설계합니다.
**현재는 DB 이관 스크립트가 제공되지 않습니다.** 전환이 승인되면 9절의 절차대로 별도 구현·검증한 뒤 적용합니다.

## 8. 권한 확인과 백업 보존 — 평가 15·17번

권한은 프로그램이 자동으로 변경하지 않습니다. 다른 사용자의 권한과 원본 보존에 영향을 주기 때문입니다.
Ubuntu 프로젝트 폴더에서 다음 **조회 명령**으로 소유자·폴더 접근·파일 권한부터 확인합니다.

```bash
id
ls -ld .
ls -l state.json
```

`id`는 현재 사용자·그룹, `ls -ld .`는 현재 폴더 자체의 권한·소유자, `ls -l state.json`은 저장 파일의 권한·소유자 확인입니다.
`No such file or directory`는 파일이 없다는 뜻이므로 첫 실행인지 경로가 다른지 구분합니다.
파일 읽기뿐 아니라 부모 폴더에서 임시 파일 생성·기존 파일 교체도 가능해야 저장됩니다.
Windows에서는 PowerShell의 `whoami`, `Get-Acl .`, `Get-Acl .\state.json`으로 계정과 ACL(접근 권한 목록)을 조회할 수 있습니다.
소유자·허용 경로를 확인한 뒤 관리자에게 필요한 접근만 복구하도록 요청합니다. `chmod 777`, 무조건 sudo 실행, 소유자 일괄 변경으로 해결하지 않습니다.
읽기/손상 원문 보관 실패로 저장이 제한됐다면 원인을 고친 뒤 새 프로세스에서 재실행해 확인합니다.

**수동 보존 정책:** 최근 정상 백업은 최소 3개를 서로 다른 시점으로 보관하고, `state.corrupt-*.json` 사고 원본은 복구 검증과 별도 보관이 끝날 때까지 유지합니다.
30일마다 저장 공간과 중복을 수동 검토하되, 기간이 지났다는 이유만으로 자동 삭제하지 않습니다. 필요한 사고 원본은 더 오래 유지합니다.
자동 백업·최대 개수 제한·자동 삭제는 구현하지 않았습니다. 정리 전 정상 데이터와 복원 가능성을 확인하고 사용자가 특정 파일만 선택합니다.

## 9. 저장 스키마·점수 변경의 데이터 이전 — 평가 18번

아래는 **향후 중요한 저장 형식 변경이 승인될 때의 이관 절차**이며 이번에 이관을 실행하거나 기존 점수를 바꾼 것이 아닙니다.

1. 게임을 모두 종료하고 기존 state.json과 사고 원본을 별도 보관합니다. 원본 해시·개수·점수·현재 코드 버전을 기록합니다.
2. 새 형식의 필드·타입·의미를 확정하고 `schema_version` 같은 식별자 도입 여부, 옛 버전 허용 범위, 실패 시 복구 방식을 정합니다.
   현재 JSON에는 schema_version 필드나 버전별 자동 이관 기능이 없습니다.
3. 새 파일/DB에 복사 변환하는 이관 도구를 별도로 만들고 읽기 전용 원본과 분리된 임시 복사본에서 시험합니다.
   예를 들어 문제당 10점으로 바꾸면 best_result의 correct가 있는 기록은 새 산식으로 계산할 수 있지만,
   구버전에서 정답 수가 없으면 최고 백분율만으로 원래 정답 수를 정확히 복원할 수 없습니다. 임의 추정하지 않고 기존 점수를 별도 보존하거나 사용자 결정으로 새 기록을 시작합니다.
4. 전체 문제·선택지·정답·최고 기록을 비교하고 한글/공백/오류 데이터, 재실행, 실패·롤백, 두 버전의 읽기 정책을 검사합니다.
5. 이관이 검증된 경우에만 새 코드와 새 저장소로 함께 전환합니다. 옛 파일을 먼저 지우지 않고 변환 로그를 보관합니다.
6. 전환 실패 시 프로그램을 종료하고 보관한 옛 코드·옛 데이터의 짝으로 복구한 뒤 재실행해 일치 여부를 확인합니다.

현재의 구버전 호환은 `played` 생략 시 점수로 추정하고 `best_result` 생략 시 None을 사용하는 범위입니다.
단순 기본 퀴즈 문구 변경과 저장 스키마 변경을 구분하며, 없는 이관 도구를 이미 구현했다고 설명하지 않습니다.
